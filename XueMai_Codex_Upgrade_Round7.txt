五、清晰呈现五项方法与实际模块

在核心方法章节开始加入“方法—输入—输出—产品模块”总览图和紧凑对应表。总览展示：

学生作答与理解检查形成证据 → K-TRACE 估计知识状态 → PATH-G 安排可执行学习路径 → DIA-GUIDE 进行学生辅导、理解检查与反馈；教师使用 CLASS-LOOP 识别班级困难，使用 DIA-TEACH 依据班级证据与教学目标生成教学行动，后续任务产生新学习证据。

这是逻辑协作关系，不要误画成每个用户请求都必须串行调用五项方法。

每个方法按同一口径呈现：教学问题、输入、输出、主要计算或协作机制、重要参数、实际源码位置、用户能观察到的结果和实验依据。

准确描述技术性质：
- K-TRACE：多维学习证据、Beta 状态估计及时间折减；
- PATH-G：先修和时间约束下的有限束搜索规划；
- DIA-GUIDE：规则诊断、策略、校验与语言模型的学生教学协作；
- CLASS-LOOP：六维学习特征、支持度距离、K-medoids 动态分组及任务匹配；
- DIA-TEACH：教师目标、班级证据、受控查询和结构化教学草稿协作。

不要把五项统一写成大模型训练算法，也不要把束搜索表述为必然全局最优。明确哪些步骤由规则与数据库计算、哪些由 DeepSeek 生成、哪些经后端校验。同步修改摘要，突出教师独立 AI 教学助手与学生辅导的区别。

六、重点强化“开发意图控制与可复现性”章节

从已有真实过程记录中提炼至少三条最有代表性的 AI 协同开发链。优先考虑：

案例一：知识图谱从拥挤流程图演变为力导向知识网络，展示用户设计目标、初始效果、反馈、代码修改及视觉验证。
案例二：教师 AI 对教学讨论或专题学情范围识别不准，展示首次异常、修正任务路由/查询范围、真实复测与对应提交。
案例三：师生 AI 角色与工具分离，或一次真实发生的教学闭环问题修复，展示权限、上下文、工具产物和测试。

选择标准是证据完整而非故事戏剧化。可换用更完整的真实案例。

每个案例应形成：原始意图 → 输入上下文与限制 → AI 产出 → 实际问题 → 修正指令或 Codex 工程决策 → 代码差异 → 测试验证 → Git 提交。

清楚区分用户真实指令、Codex 自主规划、内部子任务、工具输出与后期归纳。不能把 Codex 自己发起的任务伪装成用户原话，不能编造反馈或时间戳。报告正文用真实摘录与仓库可定位的证据链接说明，完整原始链保留于归档资料。

补充真实工程约束的解释：课程实体共用标识、接口契约、角色权限、评分与状态更新、数据库迁移、DeepSeek 后端密钥、测试覆盖与真实 CI/Git 记录如何共同制约 AI 生成代码，使开发可追溯并可复现。

七、算法实验与基线进一步深化

新增实验优先采用本地离线运行，不进行无意义的大规模实验，不提前写结论。

7.1 PATH-G
保留无约束的目标优先静态排序基线，新增满足同样先修条件与时间预算的贪心规划基线。使用相同输入、候选活动与效用函数，对比约束违规、目标覆盖、计划效用、预算利用和运行时间。区分“约束本身有效”与“束搜索比简单可行策略更优”。如结果相同或部分落后，如实保留。

7.2 CLASS-LOOP
保留24名合成学生四类错因原型案例，新增少量含混合困难、稀疏观测、缺失、噪声和近期变化的固定种子样例。验证分组稳定性、证据支持度、任务匹配和状态改变后的群组变化；可比较取消支持度机制或简化分组规则的结果。不要求混合型学生有唯一正确标签，不把原型纯度当成真实课堂准确率。

7.3 知识关联检索
将已有20个案例统一命名为“受控同词歧义场景下的知识上下文消歧实验”。增加少量同义表达、未给出知识点、不同资料片段、课程与附件相似文本、证据不足的场景。正确区分受控消歧结果与通用检索准确率。离线测试为主。

7.4 DIA-GUIDE
验证困难类型对应策略、引用与动作合法、理解检查反馈、检查失败后的策略改变、正确视频/实验/题目跳转、事件持久化；不将策略匹配等同于真实学习成绩提升。

7.5 DIA-TEACH
正式加入实验设计与结果总表。验证教师讨论和教学设计路由、专题证据范围、统计来源、时间预算、合法群组与题目、可编辑草稿与保存、正常任务发布流程及幂等性。区分请求成功、结构合法和教学要求真正满足。记录首次错误及实际修复结果。

7.6 实验记录
固定样本、时间、随机种子、代码版本与执行命令；从程序实际结果生成图表，保留失败或不利结果；实验结论不超出样本范围。合成机制实验与真实教学成效不是同一概念，但无需每页重复写免责声明。

九、视频改为真实连续录屏

检查现有 record-demo.mjs 是否仍每约500毫秒截图并在采集时使用 animations:'disabled'。系统操作画面改用真正的连续录制，优先实际 30fps，输出 1920×1080 MP4。不能仅将低频截图重编码为24/30fps并宣称操作流畅。

重点展示知识图谱拖动、搜索聚焦、栈的真实动作、交互反馈、DeepSeek流式输出等连续变化。保留鼠标和操作焦点、完整侧栏与顶部；浏览器页面保持100%比例，不为视频隐藏功能或缩小字体。

可以合理剪辑等待，但不改变数据因果与操作先后。先制作一段图谱和栈实验的短样片，实际检查运动、清晰度和压缩效果，再执行全片录制。静态图表可以单独作为辅助，但不得代替真实系统操作。

十、视频按同一个教学问题串起真实师生闭环

不要再主要按菜单列表展示功能。以“栈与队列”或其他当前系统内容完整的知识主题，围绕同一个具体学生和教师课程组织：

学生答错 → K-TRACE形成证据和PATH-G更新计划 → 学生调用DIA-GUIDE获得针对性解释/视频或实验 → 学生完成理解检查 → 教师查看该专题的具体班级证据 → DIA-TEACH形成可编辑讲评/分层方案 → 教师确认发布 → 学生收到并完成新任务 → 教师回看完成结果及新证据。

“教师发布后学生实际完成”和“教师再次查看结果”必须在视频中真实出现，不能只写在旁白里。

录制时检查课程、知识点、学生、题目、作业 ID 关联一致。使用隔离业务数据库正常触发后端逻辑，不直接篡改前端展示数字来制造进步。当前状态变化不明显时，展示真实增量、提示和证据即可，不伪造显著进步。

其他课程可少量穿插展示平台扩展性，但核心故事不要频繁切换对象。

十一、录制少量真实 DeepSeek AI 过程

新版视频至少安排两段高价值真实 AI 操作：

学生端：带题目与简短附件提问、真实模型回答、来源定位与理解检查；
教师端：围绕同一专题的班级证据提问、真实教学草稿生成与保存/发布入口。

两段的教学目的、模型上下文、工具和输出显著不同。演示要证明它不是把同一种聊天界面分别放在两个端。

先复用已经存在的真实联调结果作准备，若新增调用则以2—4次短请求为目标，默认上限6次真实模型请求，包括内部辅助调用、失败及重试。优先Flash，Pro仅在有明确价值时验证。无需重复运行此前13次联调。

历史真实回答如用于回放，应标明真实历史记录；Mock 用于其他无需实时模型的画面，不得冒充现场生成。录制本身不泄露 Key，留存实际模型、请求结果和用量。合理剪掉等待，但保留关键结果真实顺序。

十二、至少两分钟有效 AI 协同开发过程

官方规定至少两分钟 AI 协同过程复现。建议制作约135秒，留下时长余量。

建议三组真实案例，每组40—45秒：初版架构/课程对象、知识图谱或交互修复、近期教师AI专题范围/工作流修复。

每组应当以动态切换方式展示：原始 Prompt → 实际错误或旧效果 → 代码差异 → 自动化验证或真实联调 → 对应中文 Commit → 改进效果。

这是 Codex 协同开发，不是系统内教学助手的多智能体流程，两者在视频里明确区分。不要让几张很长的文字卡静止停留40秒来充当开发过程。真实截图、记录、提交和修复要对应，不补造对话与问题；旧记录标注当时日期。

总时长控制在5—8分钟，建议约7分40秒至7分50秒：
00:00—00:20：一个具体教学困难开场；

01:35—02:35：学生真实AI辅导、附件引用与理解检查；
02:35—03:45：教师证据分析、AI教学设计与任务发布；

具体秒数可据实际操作微调，总时长不得超过8分钟，真实开发证据时长不能缩水，完整教学闭环不能删除。减少配色、视图数量和菜单名称的口播，将时间留给“操作为什么重要、系统如何判断、实际产生什么结果”。

十四、配音、字幕和操作对齐

采用“先真实操作与剪辑 → 固定画面时间线 → 写解说 → 合成/录制声音 → 生成并校对字幕”的流程。不能让固定 until 秒数的操作脚本和独立 TTS 时间线互不协调。

重点对齐：语音转写出现时才介绍转写；学生完成任务画面与相应旁白相符；教师反馈出现时展示真实结果；模型输出不提前讲解还没出现的结论。

字幕准确、通常不超过两行、留足阅读时间，不遮挡输入框和关键结果。核对五项方法简称、Flash/Pro、Python、API 和所有数字的读法；检查长静音、音量、爆音、句尾裁断、字幕超前、字幕迟到。可听审则听审，若不能应完成自动语音转写回验与关键片段人工可视校对，并在验收中说明方法。
