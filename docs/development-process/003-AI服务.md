## 设计与第一次实现

Codex 决策：使用 httpx 直接兼容 DeepSeek 官方 chat/completions，关闭 thinking，不自动重试。客户端永远不能获得密钥。默认 Mock 不访问网络；教学草稿必须显式保存并保留待审核状态。AI 不更改客观评分与掌握度。

后端代理确认：SQLite get_db() 上下文连接、current_user 身份依赖、require_course 课程权限；resources、questions、knowledge_points 共享主业务表。

实现：
- ai.py：集中配置、每用户限流、超时、JSON 校验、SSE 解码、用量日志。
- ai_routes.py：按课程授权的检索/会话/引用；知识点、题目、视频字幕和学习证据上下文；结构化题目/教案/量规草稿。
- ai_smoke.py：显式 --run，发送前持久预留计数，独占运行锁，任何失败停止后续真实联调，最多 5 次，不计入常规回归。

## 实际测试反馈与修复

第一次命令：`.venv/Scripts/python.exe -m pytest backend/tests/test_ai.py -q`。
结果：16 passed，3 errors。3 个路由测试初始化时报 `knowledge_points has 7 columns but 8 values were supplied`。
实际反馈：向后端代理报告 seed INSERT 占位符错误。后端代理修复后再次运行。

第二次结果：18 passed，1 failed。测试“栈和队列的区别”检索到了二分查找讲义，原因是中文按单字切词时，“区”等普通字引入了无关匹配。
Codex 修复意图：保留中文概念的语义邻接，减少常用字噪声；不靠放宽测试掩盖召回问题。
修改：FTS 索引和查询统一使用中文二字组，过滤常用问句词，保留“栈、树、图、堆”等单字学科概念。

第三次实际结果：19 passed，1 warning，1.94 秒。警告来自已安装 Starlette 对 httpx TestClient 的弃用提示，不影响测试结果。

覆盖：Mock 零网络、Token 硬上限、401/402/429/500 不重试、超时、空/坏 JSON、UTF-8 任意字节分片 SSE、坏 SSE、限流、会话持久化与用户隔离、跨课程题目/知识点阻断、教师草稿权限、量规总分校验、烟测 5 次硬上限与失败停止。
