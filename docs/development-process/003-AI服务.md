## 设计与第一次实现

Codex 决策：使用 httpx 直接兼容 DeepSeek 官方 chat/completions，关闭 thinking，不自动重试。客户端永远不能获得密钥。默认 Mock 不访问网络；教学草稿必须显式保存并保留待审核状态。AI 不更改客观评分与掌握度。

后端代理确认：SQLite get_db() 上下文连接、current_user 身份依赖、require_course 课程权限；resources、questions、knowledge_points 共享主业务表。

实现：
- ai.py：集中配置、每用户限流、超时、JSON 校验、SSE 解码、用量日志。
- ai_routes.py：按课程授权的检索/会话/引用；知识点、题目、视频字幕和学习证据上下文；结构化题目/教案/量规草稿。
- ai_smoke.py：显式 --run，发送前持久预留计数，独占运行锁，任何失败停止后续真实联调，最多 5 次，不计入常规回归。

## 独立审查迭代

实际后续任务：主代理要求审查生成草稿权限、SSE 中断、课程资源隔离、超限零消耗与预算重启/并发，并编写独立负向测试。

审查发现并实施：服务商 SSE 若在 `[DONE]` 前关闭，旧实现可能把有部分文本的响应当作完成。现要求终止标识，长度截断也显示未完成；部分回答持久化为 interrupted，历史上下文保留未完成标记，不发送 done。FTS 引用加入资料版本，编辑后新检索读取新版本，旧会话保留旧引用片段和版本。

预算账本改为原子替换与 fsync；进程中断后的 reserved 记录保留计数并停止后续调用；已完成记录不能被覆盖，损坏账本不能自动重置。

另向后端代理反馈并由其修复：上传视频在公共媒体目录绕过课程授权、题目跨课程移动留下作业关联、删除知识点留下作业悬空引用、非数值事件可使首页统计报错。前端代理收到真实模式标识、主观题待复核状态、题型/难度和教学资源枚举等契约反馈。

实际验证：`pytest backend/tests/test_security.py -q` 得到 24 passed（6.83 秒）；该模块阻止未显式 MockTransport 的异步 HTTP 客户端，真实 API 请求 0 次。
