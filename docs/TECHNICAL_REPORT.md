# 学脉 XueMai：AI 个性化智慧教育平台技术文档

版本：0.1，本机教学闭环验证版。日期：2026 年 11 月 3 日。适用赛事：第九届传智杯 AI 创新应用挑战赛。

本文介绍平台的教学任务组织、意图控制方法、模块架构、学习状态更新、AI 服务及阶段验证结果。

## 一、问题与产品目标

教学中的学习材料、题目、观看记录和作业成绩常常分散在不同工具里。教师知道某次测验的分数，却难以直接定位到需要补充的先修知识；学生得到笼统的“继续努力”，没有可以立即开始的学习任务。只在页面中加入聊天框也无法解决这些问题，因为辅导内容没有与课程、具体错误和后续学习记录联系起来。

学脉以统一的课程知识实体为中心，将资源、题目、视频片段、实验、作业与学习证据连接。学生可以从图谱定位材料与练习，作答后更新学习状态；教师可以从学情分析中找出薄弱群体并发布针对性任务，再查看复测结果。AI 承担上下文辅导、教学草稿生成与量规评阅建议，确定性程序负责权限、评分、算法执行和状态写回。

## 二、意图控制策略

### 2.1 把用户意图转化为可检查约束

根目录 CODEX_TASK.md 是开发执行依据。工程将其中六项真实闭环、API 预算和密钥要求转换为接口与测试约束：课程授权必须在数据读取之前执行；学生题目响应不能包含答案；观看位置不等于掌握；AI 生成内容必须校验并由教师确认；常规回归不能调用真实服务。

开发从 .gitignore、安全边界与原始指令记录开始，按后端业务、前端交互和 AI 服务分工推进。各模块共享课程实体和接口约定，独立模块通过验证后提交。提交说明使用中文，对应具体功能与修复，保留从基础工程到业务集成的演进顺序。

### 2.2 上下文管理

AI 辅导的系统上下文包含课程、当前知识点、题目、视频时间与字幕、当前学生的必要学习证据，以及仅来自当前授权课程的资料片段。历史会话按用户和课程隔离，最多保留最近 12 条且总量不超过 6000 字符；课程上下文限制为 12000 字符，用户提问限制为 3000 字符。限制同时降低输入成本并减少无关信息。

资料和学生输入被明确标记为不可信内容。系统要求忽略资料中的越权指令，不虚构外部检索，不执行用户代码，不改动成绩与教学任务。教师评阅接口可以使用实际题目量规和参考答案；学生辅导接口不会把参考答案写入上下文。

### 2.3 输出约束

辅导通过 SSE 输出 meta、delta、done、error 四类事件；资料引用保留来源编号、资源 ID、标题、片段及版本。只有完整结束的流式回答才发送 done。服务商缺少终止标识、发生网络错误或达到长度上限时，界面收到明确错误，部分回答以 interrupted 状态保存，避免误导学生。

出题、备课和评阅使用 JSON 对象输出，再由 Pydantic 校验。题目答案必须匹配选项；量规分项分值必须与总分一致；所有生成结果保留待教师审核状态。服务返回草稿不代表数据库已保存，也不代表作业已发布。

## 三、系统架构

平台使用本机模块化单体架构。前端为 React、TypeScript、Vite 6；后端为 Python 3.13、FastAPI；数据库为 SQLite，启用外键、事务和版本记录。该组合能够在现有 Windows 笔记本上开发、测试和演示，不依赖云 GPU 或复杂集群。

| 层次 | 职责 | 实际代码边界 |
|---|---|---|
| 交互层 | 双端导航、课程工作区、表单、图谱、视频、实验 | frontend/src |
| 身份与权限 | 密码校验、持久会话、教师身份与课程访问范围 | backend/app/auth.py |
| 课程域 | 课程、章节、知识点、先修关系与班级 | routes_courses.py、routes_teaching.py |
| 学习域 | 题目、作业、提交、错题、事件、笔记 | routes_practice.py、routes_student.py |
| 教学资源域 | 上传解析、版本管理、私有文件访问 | routes_resources.py |
| 教育规则 | 确定性评分、掌握度更新与可解释推荐 | learning.py |
| AI 域 | 传输、预算与用量、检索、会话、结构化草稿 | ai.py、ai_routes.py |
| 数据层 | SQLite 连接、迁移、种子数据 | db.py |

业务处理不直接散落在前端组件中。前端仅提交业务输入和显示后端结果，不能自行确认教师权限、计算正式成绩或修改持久掌握度。AI 传输与教育规则分离，使 Mock、真实服务和故障模拟使用同一业务契约。

## 四、统一数据模型

课程拥有章节、知识点、资源和题目。知识点之间通过有向先修关系连接；添加关系时使用递归查询检查是否成环。班级连接课程与学生，课程访问范围由教师所有权和学生班级成员关系确定。

作业记录所选题目及班级或定向学生，提交记录学生答案、提示使用、自动分数和复核状态。学习事件记录作答、视频活动、实验操作及教师复核。掌握度表以学生与知识点为联合键。推荐和学情分析都读取同一套学习证据，避免双端显示互不相干的数据。

资源编辑前保存旧版本；AI 引用保存生成当时的片段和版本。上传文件不使用用户提供的文件名作为存储路径。教师上传视频保存在私有目录，通过认证和课程权限端点读取。仅原创合成演示媒体公开用于启动演示。

## 五、学习证据与个性化安排

掌握度采用可解释的规则估计。初始无证据值为 0.20。客观题独立正确作答增加 0.18，使用提示后正确增加 0.07，错误减少 0.14，结果限制在 0.05 至 0.98。当天同题连续正确不会反复提升掌握度。主观题提交后保持待教师复核，教师确认后再写入学习证据。

学习水平区分接触、提示后完成、独立完成与高难度迁移表现。观看、定位、做笔记等行为只能证明学习活动发生，不能直接证明独立掌握。错题与复测会更新订正状态和复习时间。

推荐优先级由未掌握程度、未订正错题和薄弱先修项组成：基础项约为 (1−掌握度)×100，每道未订正错题增加 30，每个薄弱先修项增加 8。推荐给出具体理由和视频、练习或复习入口。该规则可通过固定数据测试，后续可以在不改动业务接口的情况下调整权重。

## 六、AI 服务与本地检索

模型使用 DeepSeek 官方兼容 chat/completions 接口。模型、Token 上限、超时和频率统一配置，当前默认模型为 deepseek-flash，关闭额外思考模式，不自动重试。辅导使用流式输出；生成任务使用 JSON 模式，并在服务端进行教学结构校验。

检索在本地 SQLite FTS5 完成。资料按 600 字符分块、步长 520 字符，并绑定资源和课程。中文采用二字组，保留“栈、树、图、堆”等单字概念，过滤常用问句词，避免单字匹配引入无关资料。检索先确认课程访问权限，再在该课程索引内排序，最多返回三个片段；未找到资料时明确说明，不伪造引用。

默认 Mock 模式使用本地固定样例，支持无 API 额度时复现教学操作。接口和界面显示当前模式，区分固定样例与实时模型回答。真实模式由后端读取密钥，前端包和浏览器请求只使用平台会话。

## 七、API 预算与密钥保护

常规单元、契约和浏览器回归使用 Mock。真实联调为独立显式脚本，必须指定 --run 和抽样类型，调用前将预留计数写入持久账本。累计硬上限为 5 次，每次输出限制不超过 256 Tokens；独占进程锁阻止并发，原子替换和 fsync 保护账本写入。进程中断留下 reserved 记录、额度不足、凭据错误或服务异常时停止后续调用，不自动重试或重置计数。

2026 年 11 月 3 日完成连通性、流式辅导和结构化输出三次抽样，均成功。官方响应的用量累计输入 110、输出 110，总计 220 Tokens，占用开发联调次数 3/5。题库与班级使用本地编写的合成种子数据；真实调用账本与产品按需使用日志分开保存。

首次暂存前已创建 .gitignore，排除根目录密钥文件、.env、数据、日志与缓存；提供空值环境模板。日志仅保存状态和用量，不记录密钥或原始课程对话。推送前使用密钥扫描，避免把本地凭据或构建产物中的密钥公开。

## 八、测试与真实缺陷修复

AI 接口测试 19 项通过，覆盖 Mock 零网络、输出上限、超时、401/402/429/500、空和错误 JSON、UTF-8 任意字节分片 SSE、坏流、限流、会话隔离、跨课程上下文阻断和结构化草稿校验。独立安全测试 24 项通过，覆盖角色越权、跨课程关联、上传、私有媒体、失效会话、流式中断、资料版本和预算重启保护。两组联合运行共 43 项通过，耗时 12.32 秒。

检索测试以“栈和队列的区别”为输入，发现按单个汉字匹配会误召回二分查找资料。改用二字组并过滤常见问句词后，返回内容与教学主题一致。安全检查将教师上传视频改为私有文件访问，补充题目课程归属和知识点删除约束，并对观看事件进行类型与范围校验，防止异常输入破坏后续首页统计。

上述问题都有针对性负向测试，验证修复后既能拒绝越权或异常操作，也能保持原有课程、作业和学习记录的一致性。

全部后端回归共87项通过，最终统一脚本运行用时22.81秒。生产构建上的11项浏览器端到端测试在同一次运行中全部通过，实际用时40.1秒，覆盖教师视频表单、AI备课版本编辑与题目审核后学生作答、教师创建课程与班级、学生加入同一图谱、作业发布与结果、推荐及分层后的再次分析、视频真实播放与理解检查、笔记重开、AI引用和历史、503故障反馈、个人计划、课堂同步、实验操作与窄屏布局。算法还验证了110组排序输入、4组边界样本、每步元素不变量、BFS层序及BST中序。生产前端依赖使用官方npm审计端点检查，未发现已报告漏洞。

浏览器验证发现原生选项被视觉字母层遮挡，以及学生加入班级后顶部课程列表未刷新。修复输入覆盖层和课程变化通知后，保留原生交互断言复测。重复运行时历史数据导致测试定位歧义，则限定当前目标或容器，避免把测试问题记作产品缺陷。

## 九、复现方法

依赖版本在后端 requirements 和前端 lockfile 中固定。Windows 脚本负责依赖安装、数据库初始化、服务启动与测试。种子数据包括教师、两名表现不同的学生、两门课程、班级、知识图谱、题目、作业、错题和原创教学视频，均显式标记为合成数据。

复现步骤为安装依赖、初始化数据库、启动本机服务、使用演示账号登录、执行师生任务与离线测试。README 按赛事的 10 分钟极速复现要求组织操作路径。依赖下载时间受网络与机器环境影响；无真实密钥时可使用 Mock 完成教学操作。

代码已推送到公开GitHub仓库 Sunny1004-7/xuemai-ai-platform，并通过远程提交哈希核对。所有提交说明为中文，按功能与真实修复分阶段保留。开发证据页收集本次四个会话中的公开记录；协作正文在本机存储中部分加密，自动筛选不能代替完整原始聊天。三个核心功能另提供从本聊天可见协作卡片逐字转存的Prompt与反馈，明确其AI自主分工来源，并建议与原界面截图交叉核验。回放不伪装现场生成。

## 十、原创性、边界与后续验证

平台围绕课程知识网络、学习证据和分层教学任务设计，代码、课程种子内容和教学视频随工程创建。React、FastAPI 等开源框架作为运行依赖使用，版本信息随工程保留。

当前验证使用合成课程与学生数据，重点检查业务功能、权限和状态更新。学习规则的教育效果需要真实班级的长期观察与评价。资料解析面向文本型 PDF，扫描 PDF 需要 OCR 后再上传；视频应采用浏览器支持的编码。生产部署将进一步完善 HTTPS、账号生命周期、隐私管理和备份恢复。

后续深化包括独立入学诊断流程、题目质量和版本治理、到期通知、完整视频任务成绩卷与更长期的复习调度。目前诊断依托练习和学情证据，版本保护依托已有发布题目锁定与复制新版本；这些现有路径与尚未实现的独立功能分开说明。

复现材料包括版本历史、核心功能 Prompt 记录和 README。赛事演示按 5–8 分钟、1080p MP4 组织，包含至少 2 分钟 AI 协同过程；技术文档按不超过 30 页 PDF 的要求排版。
