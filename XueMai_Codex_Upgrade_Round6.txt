继续升级现有仓库：
Sunny1004-7/xuemai-ai-platform

你负责产品设计、前后端修改、算法实现、运行调试、自动化测试和视觉验收。普通技术与设计决策自主完成，直接实施，不停留在建议和规划阶段。

本任务书只规定系统代码、算法、数据和界面工作。正式技术文档与演示视频的修改要求由用户在启动指令中另行补充。继续维护必要的工程状态、测试结果和真实开发过程记录。

通过组标题、合理间距和当前项高亮建立层级，不再把十个入口连续铺成一列。

教师顶部帮助入口应进入教师 AI 助手，不再把教师送入学生式学习伙伴。使用应用内路由跳转，保留当前课程和相关上下文。

四、知识图谱：摒弃当前设计，重新构建知识网络

这是本轮最高优先级之一。

当前的“矩形章节容器＋长距离正交线＋整体缩小”展示方式不再作为默认设计。不能只增加曲线圆角、更换节点颜色，然后宣称完成重构。

保留后端真实知识结构、先修约束、学习状态与教师编辑能力，重做的是图谱的视觉布局和探索方式。

4.1 重新研究已有参考资料

读取此前提供的优秀智慧平台 UI 截图和前端参考，重点分析其：

圆形节点的尺寸与层级；
节点分布的疏密和节奏；
连线的轻重与方向；
知识详情的展开位置；
选中、悬浮和关系聚焦；
画布与工具栏的空间比例。

借鉴设计规律并独立实现，不把参考平台的固定示例节点替代学脉的真实课程数据。

4.2 明确新的展示方向

默认采用“轻量圆形知识网络＋自然分布＋局部关系聚焦”。

推荐以带章节软约束的稳定力导向布局作为主要路线，使用成熟布局能力，结合节点碰撞、标签避让、连线长度和视口比例优化。

可以使用 D3-force 等布局工具配合现有 React/SVG 绘制层，或经验证更适合的成熟图形方案。重点是结果，不为替换依赖而替换依赖。

默认图不再用大块矩形框把章节硬塞成几列，也不再让大量直角线绕过多个章节形成复杂走廊。

章节归属可以通过空间邻近、克制的颜色、轻量文字或柔和区域提示表达。

先修图在算法上仍然有方向和约束，但视觉上不必画成严格的工程流程图。

4.3 布局必须解决的实际问题

依据节点和关系自动生成布局，不手工硬编码演示坐标；
根据画布长宽比组织空间，避免图整体细长而被迫缩小；
节点、标签与操作热点共同参与避让；
主节点与普通节点有适当区别；
相同数据使用稳定初始条件，避免每次刷新随机跳动；
节点新增或局部编辑尽量保持其余节点位置稳定；
布局计算与界面操作分离，避免拖动时卡顿；
布局稳定后停止无意义晃动；
拖动节点与拖动画布分别有明确操作；
提供重新布局和恢复视图。

可以用同一套真实数据实现两种构图候选，自动截图比较后选定更清楚、更美观的一种。无需向用户询问设计选择。

4.4 节点与标签

知识点是图谱主体，不把每个节点做成多层仪表盘。

使用清楚的圆形轮廓、适量状态标记和稳定的字号。名称优先清晰表达，掌握度只作为辅助信息。

较长名称合理换行，完整名称可在悬浮和详情中查看。

重要知识点、当前选中节点、直接邻居和学习路径重点节点必须清晰可辨。

不要因为“适配全图”就把所有文字缩成几像素。默认视图应在内容丰富与可读性之间取得平衡；更大图通过语义缩放、局部聚焦和层级展开处理。

4.5 连线与关系阅读

连线从圆形边缘正确起止，箭头不能埋进节点；
采用自然、简洁的直线或平滑曲线，减少多余转折；
连线绘制在节点与文字下方；
当前选中节点的一阶关系突出显示，无关关系适度弱化；
悬浮或选中连线能看清起点、终点和关系类型；
查看先修链时清晰表达方向；
不同关系使用有限且一致的线型或颜色；
不要靠给每条线换一种颜色解决交错。

全图可以保留完整关系查看开关。若默认隐藏部分次要关系，必须有明确的恢复入口，不能删改真实知识结构来让截图显得清爽。

不要通过过度捆绑边导致用户无法追踪某条关系究竟连接了哪个节点。

4.6 学生与教师使用方式

学生端突出：
个人学习状态、前置知识、推荐路径，以及视频、题目、辅导、实验入口。

教师端突出：
课程结构、知识关系编辑、资源关联和对应学情。

共用图谱底座，但工具栏、详情和操作根据角色组织。

详情面板可收起，默认不要把画布挤成狭窄区域。重点知识信息可以放在精致的侧栏或底部详情区。

4.7 全屏和视口

保留真实可用的全屏探索、搜索、缩放、适配、局部聚焦和退出功能。

普通模式与全屏模式都要设计，不能只让全屏好看。

进入和退出全屏保留选中知识点及合理视角。

课程切换、章节切换、编辑、窗口变化后，画布和布局正确更新。

“适配全部内容”与“聚焦阅读”分别处理，不用反复缩小整图代替设计。

4.8 图谱验收

使用两门真实演示课程及较大测试图进行验证。

检查节点碰撞、标签遮挡、边与节点穿越、关系方向、布局稳定性、教师编辑及课程切换。

重点查看默认首屏：它应是一张清楚、有层次、具有表现力的知识网络，而不是若干缩小的流程框。

保留修改前后同课程、同视口的完整界面截图，直接比较。

五、AI 工作区基础升级：模型、附件、语音

学生学习伙伴和教师教学助手共用可靠的消息、附件与模型基础设施，但采用不同的教学工作流。

5.1 模型切换

两端均提供模型选择：

DeepSeek Flash：deepseek-flash
DeepSeek Pro：deepseek-v4-pro

开发时核对 DeepSeek 官方文档和后端 GET /models 返回的实际可用模型与能力，建立服务端模型白名单和能力配置。

模型选择必须贯穿：

前端选择；
请求参数；
服务端校验；
实际模型调用；
流式返回；
消息记录；
历史重新打开；
用量与错误记录。

不能只更改前端显示名称，实际请求仍调用同一个模型。

不要通过修改全局环境变量实现某个用户的模型切换。每个请求使用独立配置，避免不同会话相互影响。

正在生成的回答使用请求发起时的模型。生成期间切换设置仅影响后续请求，不改变当前回答身份。

默认采用 Flash，Pro 由用户选择。模型不可用时明确反馈，不能静默切换后仍标记为原模型。

在对话区域自然显示当前模型和必要状态，不在所有页面增加技术标签。

5.2 文件上传

两端 AI 工作区都增加真实可用的附件功能。

首批支持：
TXT、Markdown、PDF、DOCX、CSV，以及 PNG/JPEG 等必要图片格式。

实现完整链路：

选择或拖入文件；
显示文件卡片和处理状态；
后端校验与保存；
解析、切分或图像处理；
与当前用户、角色、课程、会话绑定；
提问时检索或使用对应内容；
回答中给出可定位来源；
历史会话重新打开后仍可追溯附件。

文档不能仅显示一个附件名称，实际回答却没有读取内容。

文本型 PDF、Word 和表格在后端解析。保留页码、章节、段落或行列等可用定位信息。

图像型内容按当前模型能力处理。当前官方模型信息中 Flash 支持图片，Pro 的输入模态列为文本；运行时以实际能力配置为准。

使用 Pro 且包含无法作为文本处理的图片时，提供清楚的处理选择，例如切换 Flash 识图，或者先获取图像内容再交给 Pro 分析。保留实际处理链和模型记录，不把其他模型的识图结果标记成 Pro 原生视觉。

DeepSeek Files API 不是任意文档解析器。不要把 PDF、DOCX、音频直接送到图片文件接口。

初始阶段不扩展压缩包和可执行文件。对文件类型、实际内容、大小、页数和单次附件数量设置合理限制。

5.3 附件与权限

附件默认只属于上传者及当前会话，不自动进入全班共享资料。

教师把附件加入课程资料，需要通过明确操作。

校验附件所属用户、课程和会话，防止通过更换 attachment_id 读取他人文件。

文件名规范化，存储采用服务端生成的标识；不使用用户文件名拼接任意路径。

文档内容作为待分析资料，不作为系统指令。引用中的指令不能获得工具权限。

删除附件后正确处理检索索引、可访问状态和相关远端文件。

前端展示短而准确的失败提示，不泄露后端路径或凭据。

5.4 语音输入

增加真实语音输入，而不是只有麦克风图标。

完整流程：

开始录音；
显示录音状态和计时；
停止或取消；
进行语音转写；
转写文字进入可编辑输入框；
用户确认后发送给 DeepSeek。

中文语音及常见英文技术词应可使用。

推荐通过浏览器录音接口采集音频，由本机轻量语音识别服务完成转写，再交给 DeepSeek 处理教学问题。可以选择 Windows 可运行的成熟 Whisper 推理实现，不需要训练模型或新增付费语音服务账号。

浏览器自带 SpeechRecognition 可以作为经过兼容性核实的补充，但不要将其作为唯一可用路径。

录音权限通过浏览器正常申请；处理拒绝授权、无麦克风、静音、超时、切换会话和取消录音。

停止或退出页面后释放音频设备。

先完成准确、稳定的录音转文字，不强行增加语音播报和实时语音通话。

语音测试必须包含真实音频经过识别服务的过程。可以用固定音频样本和自动化音频输入验证，不以直接向输入框注入文字代替语音识别测试。

六、师生 AI：建立两套不同的业务与算法流程

本轮不能只给教师增加一个聊天入口，再复用学生的回答策略。

6.1 共享基础，分离角色流程

共享：
模型服务、流式消息、会话保存、附件处理、检索底座、错误处理、用量统计。

分离：
任务识别、可读取数据、教学策略、工具集合、结构化产物、校验标准、可执行操作。

角色由登录身份和后端权限确定，不相信前端提交的角色字符串。

学生不能通过修改请求参数调用教师工具或读取教师专用内容。

6.2 学生：继续深化 DIA-GUIDE

学生端的主线：

识别当前学习困难；
检索课程与附件证据；
选择适当教学策略；
提供解释、提示或可操作学习活动；
开展理解检查；
根据结果调整下一步学习。

结合 K-TRACE、PATH-G 及现有学习记录，但避免仅凭一次回答就改变掌握结论。

教学策略至少能区别：

概念解释；
具体错误步骤；
反例辨析；
提示引导；
例题讲解；
迁移练习；
复习总结。

根据练习、测验和教师配置区分提示策略，不把所有学生问题一律处理为“永远不能给答案”，也不能在受限测验中泄露答案。

用户没有指定知识点时，通过当前对象、检索及内容匹配识别讨论范围。没有可靠匹配就按一般课程问题处理，不再强制绑定课程第一个知识点。

辅导产生的学习动作必须打开正确对象，包括正确题组、视频片段、知识关系和实验模式。

6.3 教师：建设独立 AI 教学助手

教师助手服务于“如何教”，不是把教师当成正在做题的学生。

支持四类主任务：

教学设计：
结合教学目标、课时、先修知识和课程资料生成可编辑教学安排。

题目与评阅：
辅助设计题目、讲评方案、评分量规和分层练习，衔接现有题库与批阅模块。

学情研判：
读取教师有权访问的班级、作业和知识状态，回答具体教学问题，并提供可追溯数据依据。

分层干预：
结合 CLASS-LOOP 等现有结果，为不同困难群组提出对应内容、任务和复测安排。

教师可以从导航直接进入，也可以从学情、题库、备课或视频页面带上下文进入。

6.4 教师专用协作方法

在现有架构上实现“教学目标与班级证据双约束的协作教学规划方法”，可命名为 DIA-TEACH，与学生 DIA-GUIDE 区分。

至少包含以下真实职责：

任务规划：
识别教师目标、课程、班级、知识范围、课时和预期产物，形成结构化任务。

证据获取：
检索授权课程材料和附件，调用受控学情、作业和错因查询工具。

教学设计：
结合目标与证据生成教案、题目、讲评、量规或分层任务草稿。

质量校验：
核对课程范围、知识关系、引用、数值、题目结构和任务对象，返回可编辑结果。

每一步有明确输入、输出、状态和实际工具，不只是给几段 Prompt 起不同名字。

简单问题使用轻量路径；复杂备课或学情任务才调用完整协作流程。规则、检索、统计与模型各司其职，不强制每次询问都执行多次模型请求。

6.5 教师输出应能进入实际工作

支持可操作结果，例如：

保存为教案草稿；
加入题库待审核；
生成评分量规草稿；
创建分层任务草稿；
定位相关知识点；
查看支持结论的学生或作业记录；
跳转视频活动编辑。

草稿经过教师在产品中确认后发布，不能由聊天内容直接绕过业务审核、修改正式成绩或批量给学生发任务。

这些教师操作由正常 UI 承载，开发时使用自动化测试完成，不要求用户承担手工验收。

6.6 一组必须跑通的差异化场景

学生：
“我不明白为什么这个队列操作结果不对。”
系统结合当前题目和作答，定位问题、打开队列实验、组织理解检查，并保存实际结果。

教师：
“这个班在队列和栈的应用题上分别有哪些典型错误？帮我安排一节讲评课和两组后续练习。”
系统查询真实班级数据，引用相关资料，区分错误，生成讲评与分层任务草稿，允许打开对应题目并发布。

两者的上下文、工具、产物和反馈都必须不同，不能只替换称呼。

七、检索与算法能力深化

7.1 课程与附件联合检索

升级现有 retrieval.py，而不是一加入附件就把整份文档直接拼进 Prompt。

实现：

用户、角色、课程、会话的权限过滤；
章节或段落级切分；
文档版本与片段定位；
课程材料与当前附件的联合召回；
知识点关联；
相关片段排序；
上下文预算；
证据不足时的正常处理。

现有实现按 resource_id 去重，可能丢掉同一文档中的其他相关片段。改为片段级选择与合理的文档多样性控制。

可以先强化现有 FTS/BM25，再结合知识关系和经过验证的轻量语义检索。是否增加本地嵌入模型由实际检索结果决定，不以“用了向量库”作为创新本身。

检索缓存必须包含权限范围、课程、附件集合和资料版本。

7.2 引用与正确性

回答引用能打开对应资料及具体位置。

区分：

来源确实存在；
引用位置正确；
引用内容是否支持当前判断；
结构化教学动作能否执行。

编号合法不等于回答内容已经正确。已有 VerificationAgent 的引用与对象校验继续保留，并补充必要的内容支持检查。

教师回答中的人数、分数、比例等由受控数据库查询计算。模型负责解释，不自行编造统计值。

只向界面展示真实的任务步骤、工具结果和简洁依据，不制作虚假的“多个智能体正在讨论”动画，也不要求输出模型内部思维过程。

7.3 修复教学动作映射

建立明确的“知识点／能力—实验组件—资源片段”关联，减少依赖标题包含某几个字的判断。

重点修复：

队列知识点不能再进入 stack；
视频动作不再一律从 0 秒开始；
缺少上下文时不能默认课程第一个知识点；
教师不能按自己的账号计算学生掌握状态；
理解检查、视频、实验和问题均须属于正确课程。

确保这些映射有数据或配置依据、服务端验证和自动化用例。

7.4 保持已有方法有效

保留第五轮完成的目标时间预算、计划对象关联、校验状态修复和学习反馈。

检查：

K-TRACE 的证据、时间与重复作答处理；
PATH-G 的先修约束、真实时间预算及资源可执行性；
DIA-GUIDE 的理解检查和状态转换；
CLASS-LOOP 的群组变化与知识困难匹配；
DIA-TEACH 的目标、班级证据和草稿产出。

本轮的技术提升应落在真实机制和产品能力上，不再增加只有名称的算法。

八、栈与其他交互实验重做

8.1 栈画布重新组织

当前画布很大，栈却缩在一个狭窄滚动容器里。重新设计为清晰、舒展的教学场景。

主画布应包括：

明显的栈体与栈底；
尺寸合理的元素块；
独立、清楚的栈顶指示；
待入栈元素；
出栈结果区；
当前操作与状态变化；
必要的容量或元素数量信息。

充分使用中央空间，不再保留小盒子里的横向滚动条。

栈顶文字放在正常图形布局中，不通过 right:-46px 伸到裁剪容器之外。

根据视口和元素数量调整几何尺寸；较多元素仍保持合理可读性，不能无限压缩字号。

8.2 动画由真实状态驱动

入栈：
元素从输入位置进入栈顶，原有元素和指针正确响应。

出栈：
栈顶元素离开进入结果区，新栈顶明确变化。

查看栈顶：
强调当前元素，不改变实际结构。

重置、逐步操作和过程回放保持数据一致。

动画中防止连续点击造成状态竞争；操作完成与视觉完成有明确关系。支持减少动态效果的系统偏好。

8.3 保存真正的操作过程

为实验记录增加适合当前实验的数据：

输入配置；
操作序列；
操作前后状态；
弹出或查看结果；
预测题答案；
实际检查结果；
对应知识点。

栈实验不能继续只保存与排序相关的输入字段和一个操作次数。

避免仅用“做了三次操作”作为理解或掌握的依据。操作参与与理解检查分开记录。

8.4 举一反三检查

同步检查队列、树、图搜索、排序和 Python 实验。

队列应明确队首与队尾；
树和图节点标签清晰；
控制区不会挤压图形；
较短窗口下主要操作可见；
数据与动画一致；
错误或边界操作有自然反馈。

九、系统性治理重叠、裁切和拥挤

本轮继续追求桌面端首屏完整，但优先级明确为：

内容与操作可用；
文字清晰；
布局不重叠；
再优化一屏呈现。

不能为了通过“页面没有纵向滚动条”测试，就让内容溢出、缩成小字或被页脚遮住。

9.1 题库与作业专项修复

重点检查 Practice、Workspace/Pager 和相关 CSS。

课程题库卡片采用明确的结构：

标题与筛选区；
可伸缩的题目列表区；
独立分页区。

分页不能覆盖列表，列表也不能绘制到分页上方。

优先使用类似 auto / minmax(0,1fr) / auto 的布局结构，并明确内容区的溢出行为。

分页数量根据实际容器尺寸和行内容确定，不只用 window.innerHeight 减去固定数字估算。

长题干、标签换行、字体加载、窗口变化和筛选后都需要重新验证。

可以合理减少当前页条数，或使用清楚的局部列表滚动；不要截掉最后一道题。

教师题库工具栏使用教师任务语言与操作，不机械保留学生“自主练习”等模式。

9.2 全站检查

逐一检查：

分页与列表；
固定按钮与正文；
标题与筛选器；
聊天输入区与消息；
附件卡片与输入框；
模型下拉与顶部栏；
图谱浮层与画布；
实验标签与容器边界；
表格列标题与滚动内容；
导航与底部用户信息；
弹窗、抽屉及关闭按钮。

清理造成冲突的跨轮全局覆盖规则。把布局约束归到组件本身，避免继续增加大量 !important 或 round6 覆盖补丁。

9.3 验收不能只看可见性

除了 scrollHeight 和 toBeVisible，还要检查：

最后一行内容的边界是否进入分页区；
按钮中心是否被其他元素覆盖；
标签和数字是否被裁掉；
弹层是否完整位于可用视口；
焦点是否能到达；
实际点击是否命中正确控件。

使用边界框、必要的命中测试、截图和真实点击共同验证。

要求所有 AI 主业务跑通，不接受只测 /status 或一次普通聊天后宣布整个 AI 系统可用。

同时控制用量，不做大规模压测、批量内容生成或反复评测。

大量单元、权限、结构校验、错误恢复和浏览器回归使用 Mock 或固定测试数据。

历史用量记录保留，本轮单独计数，不通过重置日志规避预算。

这个预算用于开发联调，不限制产品正常使用只能调用几十次。

10.4 小规模算法实验

离线部分可建立较充分的固定用例，不消耗模型额度。

在线部分选择少量代表性案例，比较：

纯关键词检索与加入知识关联后的证据命中；

普通教师问答与目标—班级证据—教学草稿流程。

课程和角色正确；
工具调用成功；
教学对象映射正确；
结构化草稿合法；
流程完成；
耗时与 Token。

不把少量案例结果写成学习效果、模型准确率或获奖概率。

API Key、附件原文、学生敏感信息及音频不进入公开 Git 或通用调试日志。
