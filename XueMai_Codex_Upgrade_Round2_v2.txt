# 学脉 XueMai 第二轮：师生双端系统升级与前后端深度优化任务书

## 一、任务与执行方式

继续维护并升级现有 `Sunny1004-7/xuemai-ai-platform` 工程，不重新创建项目，不覆盖既有真实 Git 历史。本轮目标是把已有的师生双端智慧教育平台提升为**视觉设计成熟、交互体验精致、个性化教学机制扎实、功能互相贯通、具有鲜明技术亮点**的高水平 AI 创新应用作品。

你同时承担产品设计负责人、视觉设计师、前后端架构师、个性化学习算法工程师、AI 应用工程师和测试负责人。请先读取现有源码、README、AGENTS.md、PROJECT_STATE.md、自动化测试、最新前端截图及赛道官方手册，形成基于实际实现的修改清单，然后**直接修改代码、运行、测试、截图复查、修复问题、逐阶段提交并推送 GitHub**。不只输出建议或效果图；所有重要改进都要在真实系统中落地。

普通的设计与技术决策由你自主完成，不要求用户参与编程、审美选择、手动调试或测试。保留已有可用业务功能和师生联动，允许必要的组件重构与后端迁移，但不能把项目重做成仅有视觉效果的静态原型。

## 二、最重要的 UI 设计准则

**“避免不必要的次级标签和说明文案，让布局本身完成解释。”**

这是以下英文要求的正式中文执行标准：**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

逐页重审标题、副标题、辅助标签、卡片说明、状态角标、侧栏口号、底部标语及各种重复帮助文案。删去不承担实际信息或操作作用的句子；能用清晰的视觉层级、间距、图标、分组、内容结构和交互状态表达的，就不要再写一段“说明书”。页面应自然、克制、大方，不应出现大量“成长脉络”“陪伴每一步”“从学习证据出发”式口号堆叠。按钮使用简洁的动作名称，数据和业务内容优先于宣传性语言。

不要把 UI 问题简单理解为修改几种颜色。需要从信息架构、排版、留白、密度、组件比例、对齐、字体层级、阴影、动效、导航和内容层次重新设计。减少重复的白卡片、彩色胶囊标签、统一 KPI 四宫格和装饰性图标；针对不同任务选择真正合适的界面结构。

保留必要且准确的错误、加载、权限、保存成功和 AI 服务状态反馈，但将技术环境信息集中于相应状态区域或“关于/开发信息”，不在每个页面重复展示“演示环境”“合成数据”“Mock”等说明。实时 AI 和 Mock 的区别仍必须真实可辨，不能用视觉美化掩盖实际调用状态。

## 三、视觉体系：以用户提供的宋式配色图为准，形成师生双主题

本节配色已依据用户提供的 9 张“宋式配色灵感”参考图逐一核对，**不再仅凭对小红书链接的猜测选色**。最终采用两套色板：学生端以「宋瓷青绿」（参考图 08/20）为主体，教师端以「茶烟米褐」（参考图 05/20）为主体。两者共享品牌、排版和组件规范，但在功能区布局、品牌层级与色彩上明显区分。参考图中的山水插画属于风格启发，不需要复制、裁切、抓取或直接作为商业 UI 的背景素材。

### 3.1 学生端——宋瓷青绿（主用色板）

来自参考图 **08/20《宋瓷青绿》**，以下五个颜色保持原图 HEX：

| 色彩角色 | HEX | 建议在产品中的用途 |
|---|---|---|
| 深青瓷 | `#2E6A67` | 学生端品牌主色、主要操作、选中状态、关键路径线 |
| 青黛绿 | `#5E8C87` | 次要操作、图谱次级节点、控件的选中背景 |
| 浅青釉 | `#A9C8BE` | 轻提示、知识图谱分组、柔和强调区域 |
| 淡青白 | `#D7E6DB` | 轻背景、选中行、分隔层与弱强调底色 |
| 纸釉白 | `#F1F0E8` | 学生端主要页面背景和大面积留白 |

学生端应呈现**清爽、专注、灵动但不浮躁**的体验。以浅暖白底承载真实学习内容，青瓷深色用于高价值操作，小面积浅青用于层次。课程、题目、学习计划和知识图谱应是视觉中心。正文深墨色可选 `#263A37`（为易读性补充的中性色，并非原图色值）。不要大量使用大面积饱和绿块，也不要把学生端做成深色科技驾驶舱。

### 3.2 教师端——茶烟米褐（主用色板）

来自参考图 **05/20《茶烟米褐》**，以下五个颜色保持原图 HEX：

| 色彩角色 | HEX | 建议在产品中的用途 |
|---|---|---|
| 茶褐 | `#7E6554` | 教师端主色、主操作、当前编辑态、重点教学操作 |
| 暖茶灰 | `#A78A73` | 次级导航、辅助交互、温和分组标识 |
| 浅檀米 | `#D4B79D` | 选中区域、图表柔和序列、编辑器轻提示 |
| 暖杏纸 | `#E9D6BE` | 次级工作区底色、行悬浮与辅助面板 |
| 宣纸白 | `#F5EEE4` | 教师端主要背景和大面积留白 |

教师端应呈现**沉稳、专业、温润、有秩序的教学工作台**，强调编辑与组织效率。正文深墨褐可选 `#352D29`（为易读性补充的中性色，并非原图色值）。不要将茶褐色大面积覆盖学情图表；高密度数据区域应优先保持清晰的白底或纸白底。

### 3.3 克制使用的辅助色与跨角色中性色

为了让图表、知识图谱的分支及少数状态更易区分，可以有限使用其他配色图中的颜色：

- **重点强调金：** `#C6A348`，来自参考图 **04/20《槐黄石绿》**。只用于少量关键成就、当前学习里程碑或教师端需要注意的操作，不作为普通按钮和正文的常规颜色。
- **灰蓝数据色：** `#607E95`，来自参考图 **02/20《雾蓝银灰》**。用于知识图谱异类关系、数据图表中的独立序列，避免所有数据都用绿色或棕色表示。
- **冷灰蓝辅助色：** `#A8C3D6`，同来自参考图 **02/20**，用于图表次级系列或微弱分组区域。
- **中性背景：** `#F7F6F2`、`#E8E9E6`，来自参考图 **09/20《月白松烟》**，适用于双端共有的登录、弹窗或跨角色表单。
- **错误与破坏性操作：** 可参考 `#8C2F2D`（参考图 **03/20《墨红金沙》**），以少量明确的错误态使用，不用于大面积装饰或常规提示。

这些辅助色服务于信息识别，不应演变为“九套颜色全部混搭”。**每个角色主要只使用自己的五色板，另外最多使用少量有明确语义的辅助色。** 颜色不是唯一的信息表达方式；状态还应有图标、文字、描边、图案或形状差异。

### 3.4 视觉落地：不仅是换色，还要重建设计系统

1. 统一设计 tokens：如 `--surface`、`--surface-raised`、`--surface-subtle`、`--text-primary`、`--text-muted`、`--border`、`--brand-primary`、`--brand-soft`、`--accent`、`--focus-ring`、`--danger` 等，为学生／教师两种主题分别配置真实值。避免把 HEX 分散硬编码进每个页面。
2. 对页面导航、表单、主按钮、题目选项、进度、图谱节点、图表和状态统一定义正常、悬浮、选中、禁用、加载和错误样式；保证浅色底上的文字清晰可读。实际核查关键文本和控件对比度；若原图色值达不到可读性要求，只在文字/描边层补充深色中性 token，不随意改变原图五色板。
3. 对学生与教师进行**不同的页面结构设计**，不只是更换主题色：学生端优先展示下一步学习任务与课程；教师端优先展示课程操作、需关注的学习证据、批改和任务发布。
4. 把现代宋式审美落实在比例、节奏、留白、字体、边界和内容排布上：温润、克制、沉静。允许使用简洁的几何线条、抽象的知识网络及少量自主绘制的 SVG 纹理，禁止直接复用用户参考图里的插画、水印、配色卡及整张画面。
5. 避免常见“AI 生成 UI”套路：大面积渐变、霓虹光晕、毛玻璃层叠、彩色胶囊标签、无意义英文装饰、重复口号、悬浮的技术图标墙及“模块说明书”式卡片堆砌。
6. **登录页**采用跨角色品牌中性色与清晰的身份入口，学生身份进入青瓷体系，教师身份进入茶褐体系。切换身份时允许非常克制的主题转场，而不是两套完全不相关的产品。
7. **知识图谱**的圆形节点及环形学习状态尽量沿用角色主色板，使用层级、大小、轮廓和局部辅助色编码关系；不得靠铺满不同颜色实现所谓“丰富”。有 25–35 个节点时仍须保持层次与可读性。
8. **学情图表**优先使用一组可区分、语义稳定的颜色，不因视觉风格牺牲数据可比性；学习数据与教师分析对应的颜色语义应一致。
9. 通过 1440×1000、1366×768、1920×1080 和移动端截图逐页校准，重点验证“是否像成熟的教育产品”“阅读是否舒适”“入口是否明确”“两个角色是否既统一又可区分”。不能只因为调色成功就认定视觉改版完成。

### 3.5 你需要实际交付的设计成果

- 两套真实运行的主题系统，以及结构合理的 design tokens 和组件规范。
- 改版后的登录页、学生首页、教师首页、圆形知识图谱、学习工作区、AI 辅导、习题与视频、学情分析和其余全部现有页面。
- 一页简短的**配色映射表**，记录每个 HEX 的原图来源、实际 UI 用途及最终 token 名称，方便后续检查，而不是写成宣传性设计宣言。
- 最新截图与改版前对照，特别关注主色使用比例、前景/背景对比、留白、内容密度、导航结构及有无多余说明性文案。

## 四、按页面进行完整视觉改版

### 4.1 登录页和产品入口——优先重做

目前是深蓝大面积背景＋空泛口号＋静态节点图＋右侧细小表单，作为比赛作品第一印象不够好。重做清晰、精致的入口：品牌识别、两种身份的自然入口、明确的登录操作、适度的产品视觉符号。可以用原创的动态知识网络、细腻图形或课程场景建立记忆点，但不能压过表单或形成无意义装饰。

**正式演示只保留一个学生账号和一个教师账号。** 登录页只提供“体验学生端”“体验教师端”两种便捷选择，去掉第三个学生入口和冗余测试信息。后台保持可扩展的多学生/多班级业务模型；修改种子、演示资料、README、截图脚本和测试脚本，确保旧版第二个演示账号不再作为默认体验内容。测试隔离场景如需多个临时用户，可以在临时测试库动态创建，不在正式演示入口展示。

### 4.2 学生首页

从“主卡片＋四个数据指标＋多组提示文案”调整为清晰的学习工作台。第一屏回答三个问题：**现在该学什么、为什么推荐、如何继续**。用真正可进入的学习任务、进度和精致课程视觉形成层次；弱化无意义累计统计。任务入口能直接跳到对应习题、具体视频片段、知识点或辅导上下文。当天任务为空时呈现有价值的下一行动，不留巨大空白。

### 4.3 教师工作台

与学生端体现不同信息结构：当前课程、待处理作业/主观题、班级关键困难、正在进行的教学任务、可直接发布的教学干预。减少同学生端共享的复制式首页布局。教师应能在一到两步内从学情问题进入题目、学生证据及针对性任务发布。

### 4.4 知识图谱——重点重构

当前 `frontend/src/pages/Graph.tsx` 使用预设 x/y 坐标、固定 SVG 视窗与矩形知识卡节点，连线端点也按矩形宽度硬编码。改成**以圆形/圆环知识节点为视觉主体**的现代知识网络；节点形态精致，具有层次、聚类和动态反馈。

必须实现并验证：

- 自动布局（有向分层或力导向＋层级约束均可），按课程、章节或知识领域形成可辨识的簇；新增节点后无需手填坐标也能合理排布。
- 圆形节点、细腻的环形学习进度、连贯的曲线连线、清晰的方向关系。节点状态不仅靠颜色区分；文字长短与缩放下仍可读。
- 缩放、平移、拖动、搜索定位、聚焦邻居、展开先修链、节点悬浮预览、单击详情、从节点直达相关视频/习题/AI 辅导/实验。
- 学生端突出个人掌握状态和学习建议，教师端突出课程知识结构、节点编辑、先修关系编辑和对应教学资源。
- 图谱自适应视口，首次打开应自动 Fit View；防止节点重叠、连线压字、悬浮遮挡、边缘裁切与大面积空白；移动端采用适合小屏的图谱交互。
- 显示内容必须来自后端课程及学习状态，不只是漂亮的模拟动画。

扩充《数据结构与算法》演示课程的知识图谱：由目前约 8 个节点提升为**约 25–35 个经过知识关系核对的节点**，分布在至少 4–6 个有实际教学意义的主题群组；建立合理先修边、难度及关联资源。保持可维护性与信息准确性，避免为了数量堆无效节点。其他课程同样应展示真实层级。

### 4.5 其余学习与教学页面

逐一重做学生端的课程与计划、智能练习、错题复习、AI 辅导、视频学习、资源、交互实验、课堂互动，以及教师端课程班级管理、AI 备课、习题作业、视频编辑、学情与分层、课堂互动。

具体要求：

- 练习界面专注题干、作答、提示、步骤反馈；选项与结果状态美观、清晰，避免辅助栏比题目更抢眼。
- AI 辅导采用有呼吸感的对话／教学工作区，公式、代码、引用和关联学习活动都能正确呈现；不用大量“AI 味”宣言填充空白。
- 视频页突出播放器、章节时间线、字幕定位、笔记和插入式检查，减少整屏等宽小卡片。
- 教师学情页突出“发现困难→查看证据→发布干预→复测跟踪”的连续操作，不只是统计指标表。
- 资源与班级列表采用更适合浏览、检索、编辑的视图，不把每个对象都做成一张重复白卡。
- 交互实验注重真实动画的质感、可操作性与学习反馈；教师和学生界面都不应出现大面积无用留白。

## 五、算法与个性化教学深度升级（本轮的重要技术任务）

不能只做 UI 换肤。当前 `backend/app/learning.py` 的掌握度主要依靠固定增减幅度（如正确、提示后正确、错误直接加减一定数值），错题普遍被归为“概念混淆”；推荐由当前掌握度、错题数量和先修薄弱项做规则加权排序。它可以支撑初版闭环，但难以体现足够的教学诊断深度。

请设计并实现**第二代可解释个性化学习引擎**，以成熟、可验证的算法构成真实能力，而非简单更名或堆模型术语：

1. **多维学习证据**：综合题目知识点、难度、独立正确性、提示级别、首次与重试、关键步骤、复习时间与迁移题表现；保留原始事件与可追溯计算依据。视频播放或进入页面不能直接视作已经掌握。
2. **知识状态估计**：使用有明确数学定义、参数和置信/证据充分度表述的模型（可比较 BKT、加权证据更新、时间衰减等适合当前小样本课程的成熟方案）；避免同题无限重复刷分，考虑不确定性与时间间隔。不要凭空宣称模型准确率。
3. **错因区分**：依据题型、学生答案、题目所测技能与步骤记录区分概念理解、程序步骤、逻辑推理、先修知识等问题；在证据不足时给出待确认状态，而不是所有错误都归为“概念混淆”。必要时使用 DeepSeek 生成结构化辅助分析，但确定性结果由业务规则校验。
4. **先修约束与学习路径**：结合知识图谱 DAG，生成可执行的“知识卡/视频片段→针对性练习→理解检查→复测”任务序列；说明推荐原因、前置条件和完成后的状态变化。区别对待基础薄弱、解题步骤错误与迁移能力不足的情况。
5. **间隔复习**：根据作答质量、时间间隔和复测结果安排后续复习，给出可查看的调度依据；支持错题订正、复测和学习计划的统一管理。
6. **教师教学闭环**：学情洞察能够下钻到具体证据，由教师执行分层任务发布；同一学生完成任务后，相关结果回流并在教师端对照呈现。区别“任务完成”“状态变化”和“教学效果证实”，不编造教育实验成绩。

为算法建立**独立的自动化测试与可重复场景验证**：相同学生在不同时序、不同提示强度、不同知识前置缺口、重复正确、错因不同和复习后表现不同的情况下，得到合理且有解释的差异化计划。可以构造真实业务流程所需的合成测试样本，但报告里明确区分算法单元验证与真实教学效果。所有新指标来自本轮实际计算。

## 六、DeepSeek 辅导与跨模块协作升级

保留现有 DeepSeek 官方 API 接入、流式会话、题目／视频上下文和课程 FTS 检索基础，重点提升**真正面向教学任务的 AI 协作**：

- 学生可从知识图谱、错误步骤、视频时间戳、复习任务一键进入同一辅导工作区，保留当前课程、知识点与对象身份。
- 建立可解释的教学策略流程：识别困难→选择教学动作（提示、反例、概念对照、可视化实验、微型测验）→获取学生反馈→决定下一教学动作。
- AI 产生结构化教学动作，后端将其映射到受支持的业务能力（定位视频片段、读取知识关系、生成练习草稿、选择交互实验、记录理解检查等）；不能只输出“建议你去练习”的文字。
- 将辅导后的理解检查与学习事件、掌握状态及推荐衔接；不同结果产生不同后续行动。
- 优化现有 `backend/app/ai_routes.py` 检索方式。目前每次请求重新删除并建立当前课程 FTS 索引；改为上传／编辑资源时增量索引、版本化引用和稳定检索，建立小规模检索正确性测试。
- 明确区分 AI 生成的解释、确定性评分、教师待复核评阅；让真实推理和用户可见的教学动作一致。

**API 预算**：现有项目记录的真实联调为 3/5 次。保留原账本和已用额度，不删除、不重置。常规单元、集成、浏览器和截图测试全部使用本地 Mock。若确需新的真实联调，应先检查剩余额度、只做少量最小请求，不能开展大规模生成实验，也不应把付费 API 作为可视化内容批量生产手段。
