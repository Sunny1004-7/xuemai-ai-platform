优先检查以下位置，并以当前工程实际内容为准：

   Courses 组件承担课程卡片、进入视频学习和加入班级等操作。

   内容扩充主要覆盖 CS201“数据结构与算法”。

   推荐调用仍使用默认 30 分钟预算，候选活动普遍使用固定预计时长。
   实测改变个人目标 daily_minutes，并未改变规划预算。

   finalize_collaboration 在 verification.passed 为 false 时，仍保存 status='verified'，并进入 awaiting_check。
   校验结果与流程状态不一致，需要修复。

四、学生导航与师生双端课程切换

4.1 删除学生端“我的课程”独立模块

移除学生侧栏中的“我的课程”，不再保留一个用于重复选择课程的独立主页面。

教师端“课程与班级”继续保留，它承担课程管理和班级组织，不属于本次删除范围。

删除导航前，整理所有相关路由和入口：

学生首页“全部课程”；
原课程卡片；
加入班级；
进入视频学习；
课程资料；
历史 /courses 链接；
自动化测试中的导航断言；
截图脚本中的页面清单。

把必要能力迁移到顶部课程选择器、当前课程工作区或合理的快捷操作中。

“只保留顶部课程切换”指统一课程选择入口，不是删除视频学习、课程资料和加入班级等教学能力。

学生在首屏应能找到当前课程的视频、资料与学习任务。旧 /courses 地址可以合理重定向，不出现死链接或空白页面。

4.2 重做顶部课程选择器

学生端与教师端共用一个设计成熟的课程选择组件，使用各自主题颜色。

不要继续直接展示系统原生下拉框的粗糙展开样式。

组件应具备：

清晰的当前课程名称；
适当的课程图标；
明确但克制的展开指示；
与整体设计一致的弹出面板；
当前项选中标记；
舒适的行高、留白和悬浮反馈；
较长课程名称的合理处理；
必要时的课程搜索；
键盘选择、Enter 确认和 Escape 关闭；
点击外部关闭；
正确的焦点恢复。

课程数量较少时保持简洁，不为了两个课程增加多余筛选器、标签和描述段落。

学生端可以在面板底部提供一个轻量“加入班级”入口；教师端可提供“管理课程”入口。不要把选择器做成另一个复杂管理页面。

弹层不能被顶部栏、父级 overflow 或图谱全屏层遮住。窄屏下也要能够完整操作。

4.3 课程切换必须是完整的上下文切换

切换课程后，正确更新：

目标与计划；
知识图谱及其章节、选中节点和视图；
习题、作业与错题；
辅导历史和当前会话；
视频、字幕和笔记；
实验活动；
课堂互动；
教师学情与班级筛选。

清理不属于新课程的 question、knowledge、resource、assignment、conversation、chapter 等对象引用。

保留当前功能模块；如果新课程没有相同对象，回到该模块在新课程中的有效默认状态。

当前 Graph 组件中的章节、搜索、聚焦模式、详情和选中对象需要一起核查，避免切换后仍使用上一门课的章节 ID，形成空图。

请求处理中切换课程时，取消或隔离旧请求；旧课程结果不得在新课程页面回写。

重点检查 useApi 在新请求完成前保留旧数据的行为，以及 AI 流式回答在切换课程后的终止和状态恢复。

课程切换应在刷新、浏览器前进后退和深链接打开时保持一致。

五、演示内容建设：每门课程、每个模块都要扎实

5.1 本轮内容建设的基本原则

正式展示继续保留一个学生快捷登录入口和一个教师快捷登录入口。

教师后台保留真实规模的多个班级成员，不将“两个体验入口”误解为“数据库只有两个用户”。

已有班级数据可继续使用。本轮重点不是无限增加人数，而是：

补齐每门课程；
补齐主要体验学生；
补齐历史与当前任务；
补齐不同模块之间的关联；
提升题目、讲义、视频和教学案例质量。

不能只把数据结构课程做丰富，而把 Python 课程保留为极简示例。

正常启动应用后，就应能直接看到完整教学情境，不需要先运行截图脚本、录屏脚本或人工创建内容。

5.2 建立统一的教学样例初始化与升级机制

设计可维护、版本化、幂等的内容包，例如按课程组织的 seed manifest 和专门的补全脚本。

要求：

使用课程代码、样例实体稳定标识等定位内容，减少对固定数字 ID 的依赖；
新安装与现有数据库升级都能得到完整内容；
重复运行不产生重复学生、重复题目、重复目标、重复对话和重复学习事件；
保留已有真实用户修改与记录；
数据库结构变更使用迁移；
正常重启不反复覆盖状态或把已完成任务恢复成未完成；
支持在隔离的审阅数据库中重建相同样例；
记录固定随机种子、内容版本和时间基准；
需要重置时，仅重置明确标记的样例数据，不清空整个数据库。

把正式样例准备与截图采集分开。截图脚本读取已准备好的系统；需要新增交互状态时，只在隔离副本中执行。

5.3 两门课程的基础内容规模

“数据结构与算法”和“Python 程序设计”都应形成可展示的完整课程单元。

建议每门课程达到：

5—8 个有教学意义的章节；
约 25—40 个知识点；
足以表达真实先修与知识联系的关系边；
至少 30 道已审核习题；
进入普通课程练习时至少能访问 10 道可作答题；
至少 5 种合理题型；
基础、应用、推理或迁移三个层次的内容；
多份讲义、教学方案和关联资料；
至少 3 个真正可播放的课程视频片段；
多个教师作业与阶段测验；
多个课堂活动及历史回答。

这些数量是内容完成度目标，不是凑数任务。不要把同一道题改变量名复制几十次，也不要为了让图谱复杂而添加错误的先修边。

对于已经超过目标的内容，重点完善质量、关联和题型分布。

5.4 Python 课程重点补齐

可以围绕以下主题组织：

变量、类型与表达式；
条件与循环；
字符串、列表、元组、集合与字典；
函数、参数与作用域；
异常与文件操作；
面向对象基础；
综合问题求解。

知识关系、题目、讲义、视频与实验应相互对应。

不要把数据结构课程的排序视频换个标题，当成 Python 全课程的视频内容。

5.5 主要体验学生：目标与计划

每门课准备约 3—5 个有实际内容的学习目标，以及 10—16 条学习安排。

体现：

进行中的目标；
已完成的阶段目标；
当前待学内容；
今日安排；
后续计划；
已完成学习记录；
到期复习；
与教师作业相关的任务。

目标应绑定相应知识点；计划应关联实际题目、视频、资料或实验。

示例可以是：

掌握循环条件与边界；
完成列表遍历和函数参数训练；
理解队列在广度优先搜索中的作用；
完成一次错题订正与迁移复测。

不要只添加“好好学习”“完成课程”等无具体内容的目标。

5.6 智能练习、作业与错题

每门课程配置足量、多题型、多难度的可用题目。

重要知识点尽量有不同角度的练习，而不是只有一道题。

为主要体验学生准备：

历史正确作答；
具有具体错因的错误作答；
提示后完成；
独立复测；
部分待教师复核的主观题；
已完成与未完成作业；
已订正、待订正、到期复习的不同状态。

当前作业和练习列表必须准确显示题量、作答进度和所属范围。

界面中一道题一屏作答是合理的，但必须有清晰的题号导航、总题数和范围切换，不能让用户误以为整个系统只有一道题。

若从知识点进入的专题范围只有少量题，清楚显示当前筛选，并提供“全部练习”操作。

5.7 AI 辅导历史

主要体验学生在每门课程中准备约 4—6 段内容不同的辅导历史，每段具备有意义的多轮问答。

覆盖：

概念理解；
错误步骤；
视频片段提问；
反例对照；
提示引导；
理解检查与反馈。

会话有自然的标题、时间、知识点和上下文，能够正常打开并继续提问。

历史内容可以由本轮编写的教学样例导入，不需要为填充历史而批量调用 API。

在数据元信息中准确保留样例来源，不伪造 DeepSeek 实际调用次数、用量或真实开发记录。产品页面保持自然，来源说明集中在必要位置，不重新增加满屏“演示”“Mock”标签。

通过正常后端数据结构保存历史，不能只在前端写死几条聊天气泡。

5.8 课堂互动

每门课准备多个当前与历史活动，覆盖课堂提问、小测或教学反馈。

至少包含：

一个可参与的当前活动；
若干已结束活动；
主要体验学生的历史参与；
不同学生具有内容差异的回答；
教师查看参与与反馈的操作。

不要只有“今天的思考”一张卡片，也不要让所有学生提交相同句子。

结束的活动在学生端仍可查看自己的历史回答；教师端能够浏览活动记录和参与情况。

5.9 视频、资料、笔记和实验

视频需可播放、有有效字幕、时间戳、知识点关联及互动检查。

主要体验学生应有少量视频进度和时间戳笔记。

资料包含不同章节的讲义、例题讲解和教学方案，不只是统一模板文本。

实验应提供可运行的预设案例、操作记录和必要的理解检查。

检查 Experiments.tsx 的课程适配：目前实验类型主要围绕排序、树、图、栈、队列，不能切到 Python 后仍使用无匹配知识点的实验入口。

为 Python 设计对应的轻量实验，例如：

条件分支与变量状态；
循环逐步执行；
列表操作与结果预测；
函数调用与参数变化。

采用受控教学组件或有限解释执行，不将任意代码直接交给服务器执行。

5.10 教师端内容与学生端一致

教师端应自然看到：

已有课程与章节；
有正常人数的班级；
多份资料和教案；
完整题库；
多次作业与测验；
不同完成状态；
待复核题目；
课堂活动；
有差异的学情；
已有分层任务及后续反馈。

所有统计由实际记录计算。

不能出现班级人数与成员不一致、作业总分与题目不一致、错题与作答不一致、教师端与学生端掌握状态矛盾的问题。

5.11 时间与内容真实性

建立统一的样例时间基准，使最近学习、当前任务、到期复习和未来计划能够合理展示。

区分业务发生时间与样例导入时间，避免把所有历史事件都集中到启动当天。

检查作业发布、学生作答、教师复核、后续反馈的时间先后。

样例中的“进步”“完成”“待复习”等状态必须来自对应事件，而不是直接写一个好看的结果数字。

六、桌面端单屏工作区：本轮最重要的布局要求

6.1 目标定义

在浏览器 100% 页面缩放下，每个模块的主要工作区、关键内容和主要操作应完整出现在当前视口中，尽量不需要滚动整张页面寻找下方区域。

“一屏完整”不是把几十条记录和整篇正文同时挤在同一屏。

正确的实现方式是：

一屏呈现完整功能结构；
当前任务与操作完整可见；
大量记录分页展示；
不同任务通过标签页切换；
详情进入侧栏、抽屉或独立阅读状态；
长正文、聊天记录等使用受控局部阅读区。

优先使用分页和视图切换解决列表长度，不把所有长页面换成多个并排长滚动条。

6.2 禁止通过隐藏内容伪装完成

不得采用以下方式：

缩小浏览器缩放；
整体 transform: scale；
把正文字号压到难以阅读；
给 body 设置 overflow:hidden 后直接裁掉页面下半部分；
把内容 display:none 却没有访问入口；
只展示前三条记录并隐藏其余数据；
截图时使用特殊样式，实际运行仍是长页面。

普通正文维持约 15—16px，按钮、导航和主要表单约 14—16px。辅助元数据可适度更小，但不成为主要阅读字号。

6.3 建立统一工作区布局

建议采用：

固定高度的应用外壳；
顶部栏；
页面标题和必要工具栏；
可伸缩的主体区域；
在主体内部组织列表、画布、详情和操作区；
固定可见的分页或提交操作。

以实际浏览器可用视口为依据，使用合理的 Grid/Flex、min-height:0、minmax(0,1fr) 和容器尺寸计算。

不要把显示器分辨率直接当成网页内容高度。浏览器工具栏、收藏栏、侧边栏与系统缩放会减少实际可用空间。

现有 graph.css 中固定 660px、宽屏 760px 等高度需要纳入调整，不能在较矮窗口中继续撑长页面。

6.4 逐模块设计

学生学习概览：
当前学习任务、核心进展、下一步行动置于同一屏；趋势和能力表现采用紧凑图表或切换视图；近期活动显示有分页或明确详情入口的摘要，不继续纵向堆叠所有卡片。

目标与计划：
采用目标列表与计划详情的并列结构，或“目标／今日／本周／历史”标签组织；保留新建、修改和完成操作；多条计划分页，不将每个目标的所有文字全部展开。

知识图谱：
工具栏与图谱画布共同适配剩余空间；详情可收起；画布尺寸随视口变化；搜索、模式切换、Fit View 和全屏始终可见。

智能练习：
题目、作答区、题号导航和提交按钮构成稳定工作台。解析与反馈通过标签页或详情面板呈现，不在提交后把整个页面向下撑长。长题干允许局部阅读。

AI 辅导：
会话列表、对话区、教学上下文构成固定工作区；输入框始终可见；消息在对话区内部滚动，不带动整个网页跳动。检查 scrollIntoView 的作用范围。

错题与复习：
错题列表与当前订正工作区并列，采用分页、筛选和状态切换；不同时展开全部错题和全部解析。

视频学习：
播放器、章节或字幕区、笔记与检查题组织为一屏工作区；字幕、笔记、课程目录使用标签页；不要在播放器下方无限叠放时间线、视频列表与所有检查题。

课程资料：
分页列表与详情阅读模式配合；短摘要位于列表，完整内容进入阅读区；入口从当前课程工作区或顶部课程菜单可达。

交互实验：
画布、参数、播放控制与当前检查任务一屏可见；长解释收进合理的详情区域；保留主要操作，不压缩画布至失去表现力。

课堂互动：
用“进行中／已结束”与活动选择组织页面；左侧活动列表、右侧当前内容或反馈；参与记录分页，不同时展开所有活动回答。

教师工作台：
当前课程、关键待办和教学关注点一屏可见；详细数据进入对应模块，不复制整个学情分析页面。

课程与班级：
课程、章节、班级、成员采用明确标签或主从布局。成员列表分页；编辑使用表单抽屉或对话框，不把全部表单放在主页面下方。

教师题库与作业：
“题库／作业／批阅”分成明确工作视图。题库分页，当前题目与编辑操作在详情面板；作业和成绩分页。重点消除当前数千像素的长页面。

教师资料与备课：
“资料／教案／备课”使用适合任务的视图；资料分页；AI 备课编辑器占据主体空间；保存、生成和发布操作保持可见。

教师视频教学：
播放器与时间轴编辑器使用独立工作状态；字幕、检查题、知识片段编辑通过标签切换，避免将所有编辑表单一次展开。

学情与分层：
保留知识矩阵、分层、学生轨迹、干预等标签；热力图按学生、章节分批呈现；固定行列标题与必要图例；详情钻取，不把整班所有记录拼成一张长表。

6.5 移动端与可访问性

单屏优先针对桌面和笔记本。

窄屏与放大阅读时允许自然纵向滚动，保留内容与操作可达性，不强行套用桌面固定高度。

较短桌面窗口优先使用更合理的分页和标签组织；仍不足时允许明确的局部阅读区域，不裁切内容。

七、知识图谱：补内容，也改善默认呈现

现有图谱功能继续保留：

圆形节点；
关系连线；
章节、全图、局部、先修链；
搜索；
缩放与平移；
详情；
全屏；
教师编辑。

这轮不重新推翻整体视觉，而要解决“默认进入后只见一个圆球、内容显得单薄”的问题。

7.1 两门课程都有完整知识网络

分别建设合理的章节、知识点和先修关系。

先修方向准确，支持实际路径规划。若实现其他关系类型，单独表达，不把“相关”混同为“先修”。

7.2 默认视图根据内容规模选择

不要让所有课程机械使用相同默认模式。

对于约 25—40 个节点的课程，优先形成清楚的全图或章节聚类知识网络，让用户一进入就看到完整结构和适量知识细节。

章节总览、局部邻居和先修链继续作为可切换的探索方式。

节点较少的自定义课程应自然展开现有知识点，不把它们再次折叠为一个巨大章节球。

保留内容真实数量，不能用无语义装饰节点制造复杂度。

7.3 默认选择与课程切换

普通进入时，不因历史测试参数长期默认只展示某个知识点的三个邻居。

从特定题目、视频、学习任务进入时，再根据上下文聚焦对应知识点。

按用户与课程保存必要视图偏好，并验证其在当前课程中仍有效。

课程切换后正确处理章节、知识点、搜索词、过滤、布局缓存和视角，不出现空画布或其他课程残留。

7.4 美观与可读性

完整网络必须有层次，节点不重叠，标签不被线条遮住，章节簇可辨识。

图谱复杂度来自真实教学结构，不来自过多颜色、连线和装饰。

保持重要标签可读；全图适配和阅读聚焦分别提供；全屏退出恢复正确视角。

八、算法与教学方法：修复真实问题，深化实际闭环

保留并完善现有 K-TRACE、PATH-G、DIA-GUIDE、CLASS-LOOP。

本轮不增加一批新名称，重点让现有方法实际兑现其能力。

8.1 PATH-G 接入真实目标与时间约束

当前个人目标的 daily_minutes 没有真正进入规划预算，需要修复。

要求：

个人目标、今日可用时间与教师任务参与规划；
明确多目标情况下的时间预算取值策略；
活动预计时长根据资源类型和内容确定，不全部固定为 8 分钟；
区分“本次预算内路径”和“后续候选”，前端不把两者当成同一份今日计划；
已完成活动、到期复习和先修状态影响下一次规划；
预算不足时给出可执行的短路径，不悄悄超出预算。

通过自动化用例验证：同一学习状态下，10 分钟、30 分钟、60 分钟安排满足各自预算；增加目标、完成先修活动后，路径产生有依据的变化。

8.2 把计划绑定到具体学习对象

现有 study_plans 主要保存 kind 和 knowledge_id，“开始”多为跳转到一个模块。

改进为可执行学习活动，按需要关联：

course_id；
knowledge_id；
resource_id；
question_id 或题目集合；
assignment_id；
experiment_id；
video_timestamp；
完成判据；
对应学习事件。

例如“学习 Python 列表切片视频”应打开对应视频与片段，而不是打开该课程的第一段视频。

“完成函数参数练习”应进入匹配题组，而不是任意题目。

学习活动完成后回写计划进度；学生手动勾选仅代表自报完成，不直接提高知识掌握度。

8.3 修复 DIA-GUIDE 校验状态

重点检查 finalize_collaboration。

当前校验失败仍写入 verified 的逻辑必须改正。

状态应反映真实结果，例如：

校验通过；
部分动作可用；
需要修正；
生成失败；
等待学生检查；
已收到反馈。

只有有效的理解检查真实存在时，才进入等待检查状态。

删除了非法动作或引用后，应重新检查剩余输出，不能自动将其视为完全通过。

关联课程、知识点、资源、题目和理解检查应从后端核验，不只检查 href 前缀。

补充“无有效动作”“错误引用”“不存在的检查题”“跨课程资源”“部分修复成功”等测试。

8.4 保持协作方法的实现与表达一致

现有 DIA-GUIDE 使用规则和数据库工具完成部分诊断、策略与校验，并由模型承担教学内容生成。

继续发展这种低成本、职责明确的协作方式。

不必为了显得是多智能体而强制增加三次或更多模型请求。

让不同职责对应真实输入、状态、工具、输出和反馈，展示实际教学动作，而不是流程标签动画。

8.5 K-TRACE 与学习数据一致

检查时间衰减、提示权重、同题重复折减和证据充分度在新样例中的表现。

未学习与学得不好要区分；
视频观看与独立理解要区分；
重复答对不应无限刷高掌握；
主观题待复核不应提前视为确定性正确；
新旧数据升级后不应重复累计证据。

学生首页、图谱、推荐和教师学情应使用一致的指标定义与计算结果。

8.6 CLASS-LOOP 与具体困难匹配

不仅按技能类型选几道通用题，还应结合群组成员的实际薄弱知识点、先修缺口和课程任务选择干预内容。

同样是“操作步骤问题”，栈操作与 Python 循环边界应得到不同的任务。

检查证据不足、少量学生、组别变化和重复发布等情况。

干预完成后展示任务状态与新证据变化，不把合成样例中的差异写成真实教学实验效果。

九、数据覆盖与展示质量检查机制

新增一套可自动执行的“课程内容覆盖检查”。

至少按课程检查：

章节和知识点；
关系边；
已审核题目及题型分布；
视频、讲义和教案；
教师作业及其状态；
主要体验学生的目标和计划；
作答、错题、复测；
辅导历史；
课堂活动与参与；
笔记与实验记录；
教师学情和干预案例；
无效关联、重复实体和时间矛盾。

生成供开发验收使用的结构化结果，而不是在产品首页显示一份工程检查报告。

初始丰富数据与真正的空状态都需要测试：

演示账号默认展示丰富内容；
新建空课程应展示合理空状态；
搜索无结果不能伪造数据；
数据加载失败不能用演示数字掩盖。

十、跨模块体验与工程质量

10.1 保留四个主要教学模块

习题、辅导、视频学习、知识图谱必须继续作为完整能力存在。

移除“我的课程”导航后，视频与资料的可发现性不能降低。

10.2 统一对象上下文

不同模块跳转时携带正确课程和对象标识。

尤其检查：

计划到练习；
图谱到视频；
视频到辅导；
错题到理解检查；
教师学情到任务发布；
任务完成到教师反馈。

10.3 防止请求和状态串线

切换课程、切换题目、打开其他会话、退出登录时，处理正在进行的请求和本地编辑状态。

旧请求不能覆盖新页面；
未保存修改不能被无提示丢弃；
加载状态不能长期卡住；
AI 输入框和提交按钮不能因旧 busy 状态失效。

10.4 列表分页与后端一致

新增分页时保证总数、筛选和排序准确。

不能前端先截断数据，再用截断后的数量计算班级统计。

题库、资料、作业、学生列表和课堂活动按实际需要支持服务端分页或经过验证的轻量分页。

页码变化、课程变化和筛选变化时正确重置选中对象。

10.5 API 用量

正式教学功能使用已经配置的 DeepSeek 官方 API。

常规回归、样例生成和截图采集使用本地数据及测试替身，不批量消耗额度。

真实联调只验证少量代表性场景，并记录实际调用次数、Token 和失败情况。

不为填充聊天历史、题库或班级样例进行大规模付费生成。

十一、验收：不再只证明“有截图、有测试”

学生端、教师端都要分别切换到两门课程，检查每个模块。

不要只在默认的数据结构课程下验收。

课程切换后，页面、数据、图谱、题库、AI 上下文和教师分析全部一致。

11.3 桌面首屏验收

至少覆盖以下浏览器内容视口：

1920×1080；
1440×900；
1366×768；
1366×650 或接近真实笔记本浏览器可用高度的短窗口。

浏览器页面缩放保持 100%。

对桌面主要模块检查：

document.scrollingElement 的 scrollHeight 与 clientHeight；
页面主操作区是否位于可视范围；
分页与提交按钮是否可见；
内容是否通过正常入口完整可达；
是否存在隐藏溢出、不可见焦点或被遮挡弹层；
是否因固定高度导致底部内容丢失。

无整页滚动应通过真实布局实现。

聊天、长文阅读等允许必要的局部滚动，但不能用多个巨大内滚动区替代信息架构设计。

移动端及放大阅读状态单独验收，优先保证可读和可操作。

11.4 截图要求

主要验收截图使用当前视口截图，而不是依赖 fullPage:true 长图。

每张截图记录角色、课程、路由、视口、选中标签或分页状态。

分别检查每个模块的首屏、分页后内容、关键详情和主要操作状态。

截图必须来自实际运行页面，不注入仅用于截图的隐藏规则，不缩小页面比例，不临时篡改显示数据。
